# SW 개발 단계와 검증 기준

이 문서는 2026-09-09 최소 조건 검토의 후속 제안입니다. 아직 네이티브 영상 엔진 구현은 시작하지 않았습니다.

사용자 확정 목표는 **동시 4입력·최소 2출력**이며 **OUT 1 = PGM, OUT 2 = PVW**입니다. UHD는 **2160p59.94**, HD는 **1080i29.97(59.94필드/초)**이며 세션에서 한 포맷을 선택합니다. 두 포맷 동시 출력은 구현 범위에서 제외합니다.

## 단계별 산출물

| 단계 | 산출물 | 통과 기준 |
|---|---|---|
| 0. 조건 확인 | 기술 검토, 보유 장비 확인, 초기 Git 이력 | 사용자 확정 사항과 가정 분리 |
| 1. 입출력 조사 | C++ 장치 조회 및 테스트 패턴 출력 도구 | 두 SDK의 장치·모드·프로파일 조회, KONA 5 펌웨어 확인, 동일 포맷 2출력 동시 개시를 외부 계측기로 확인 |
| 2. 기본 엔진 | DeckLink 기반 2입력·1출력 CUT/MIX 중간 시험 | 지정 포맷에서 프레임 드롭·전환 타이밍·오디오 동기 측정. 최종 채널 수 시험과 구분 |
| 3. 필드 처리와 DVE | UHD 합성과 HD 필드 처리, PIP·2분할·변환·프리셋 | 1080i 입력·출력 필드 시간과 순서, DVE 움직임, 색·전환 끝 상태 확인. 혼합 입력 변환 경로도 설계 |
| 4. 두 제조사 통합 | AJA 어댑터와 4입력·2출력 구성 | UHD 4입력·2출력 및 HD 4입력·2출력을 각각 검증, 출력별 라우팅·신호 손실·재연결·시계 차이 확인 |
| 5. 운용 시험 | Qt 조작 화면, 설정 저장, 상태·오류 표시 | 합의된 지연·연속 운용 조건 충족, UI 부하가 PGM에 미치는 영향 측정 |

UI 시안은 실제 엔진 상태와 연결한 뒤에만 연결됨·녹화 중 등의 상태를 표시하도록 전환합니다. 화면만으로 하드웨어 검증을 대체하지 않습니다.

## 첫 실기 시험표

각 결과에 카드 모델, SDK/드라이버/펌웨어 버전, 포트, 픽셀 포맷, 프레임률, PC 슬롯 구성과 시험 시간을 함께 남깁니다.

| 시험 | 기록할 결과 |
|---|---|
| UHD 4입력·2출력 | 2160p59.94 입력 4개와 동일 포맷 출력 2개를 동시에 개시. 출력별 카운터·누락·영상 역할·움직임을 외부 수신 장치에서 확인 |
| HD 4입력·2출력 | 1080i29.97(장비 표기 1080i59.94) 입력 4개와 동일 포맷 출력 2개를 동시에 개시. 각 출력의 필드 순서와 시간 변화 확인 |
| 세션 포맷 선택 | UHD 또는 HD 선택을 전체 출력에 일괄 적용. 혼합 출력 포맷 요청을 거부하고 선택한 신호가 두 단자에 나오는지 확인 |
| 입력 → 출력 | 평균·최대 지연, 입력/출력 프레임 카운트, 누락·반복 |
| CUT / MIX | 프레임 경계 반영, 전환 길이, PGM/PVW 교환 동작 |
| DVE 2레이어 | PIP와 2분할, 경계 크롭, 회전, 투명도, 프리셋 복원 |
| HD와 UHD 혼합 | 해상도, 종횡비, 색 범위, 프레임률 변환 결과 |
| 인터레이스 | 30000/1001 프레임률과 60000/1001 필드률 매핑, 입력 디인터레이스와 출력 필드 구성, 이동 물체·DVE의 빗살·떨림·시간 해상도 |
| 출력 라우팅 | OUT 1에 PGM, OUT 2에 PVW를 서로 다른 영상으로 출력. PVW 선택·DVE 편집이 TAKE/AUTO 전 PGM을 바꾸지 않는지 확인하고, 전환 완료 후 버스 상태와 출력 영상 일치 확인 |
| 오디오 | 48kHz 경로, 채널 선택, 전환 클릭, 장시간 A/V 드리프트 |
| 입력 신호 손실 | 정책에 따른 마지막 프레임 유지 또는 블랙, 복구 후 동기화 |
| GPU·CPU 과부하 | 제한된 큐 유지, 누적 지연, 출력 반복·드롭 표시 |
| 다중 카드 | 같은 기준 신호 / 독립 시계 조건, 두 SDK 동시 안정성 |
| 연속 운용 | 초기 1시간 측정 후 8시간 시험 제안. 확정 요구는 별도 합의 |

지연 목표는 최초 루프스루 측정 후 정합니다. 측정 전 1프레임 지연이나 UHD 4채널 무손실 처리를 약속하지 않습니다. 최종 포맷별 지원 표에는 실제 통과한 조합만 표기합니다.

UHD 시험과 HD 시험은 별도 실행합니다. 각각 입력 4개·출력 2개가 동시에 동작해야 해당 모드의 최소 채널 수를 통과한 것으로 봅니다. 4입력·1출력 또는 2입력·2출력 시험 결과로 대체하지 않습니다. 출력 3개 이상은 최소 2개를 충족한 뒤 실제 장치 능력에 따라 확장합니다.

## 코드와 버전 관리 제안

후속 구현 시 아래 모듈로 분리합니다. 지금 이 경로에 기능이 구현되어 있다는 뜻은 아닙니다.

```text
apps/desktop/             Qt 조작 UI
engine/core/              시간, 프레임 풀, 소스와 출력 상태
engine/video/             포맷 변환, GPU 합성, DVE
engine/audio/             채널 라우팅, 동기화, 지연 보정
io/decklink/              Blackmagic SDK 어댑터
io/aja/                   AJA NTV2 SDK 어댑터
tools/device-probe/       장치 및 모드 조회
tests/                   상태·타이밍 및 영상 경계 사례 검증
docs/                    결정 사항, 시험 결과, 운용 설명
```

- 기준 브랜치에는 검증된 변경을 반영하고 기능 개발은 `codex/<작업명>`을 사용합니다.
- 변경마다 목적과 검증 결과를 커밋 또는 PR에 기록합니다.
- 카드가 없는 CI에서는 공통 코어와 모의 입출력을 검증합니다. 실제 SDI 시험은 카드가 장착된 PC에서 수행합니다.
- SDK는 로컬 설치 경로를 빌드 설정으로 전달합니다. 제조사 SDK 원본과 드라이버 설치 파일을 저장소에 일괄 복사하지 않습니다.
- 도입 라이브러리와 배포 방식은 구현 단계에 결정합니다. 프로젝트 라이선스와 상용 배포 조건은 아직 정하지 않았습니다.
- 시험 영상·로그는 기본적으로 로컬 제외 경로에 둡니다. 공유가 필요한 시험 결과는 식별 정보 없이 요약해 문서로 남깁니다.

## 현재 검증 상태

- 확인 완료: 공식 제품·SDK 문서 검토, Windows 장치 인식, 드라이버 버전, 기존 화면 코드 읽기.
- 기존 웹 시안: JavaScript 문법 검사 통과. 실제 브라우저 동작이나 카드 기능 시험을 의미하지 않습니다.
- 미실행: SDK 컴파일, 실제 영상 입력·출력, UHD 부하, DVE 화질, 오디오 및 연속 운용 시험.
- GitHub 대상: 사용자가 생성한 공개 저장소 [coremon91/sw](https://github.com/coremon91/sw). 원격 동기화 상태는 작업 결과에서 별도로 확인합니다.
