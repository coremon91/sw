# INPUT 4 내장 플레이어

2026-09-11. 기존 4K 플레이어의 FFmpeg 런타임을 SW에 연결했습니다. 파일의 영상·오디오를 직접 합성 엔진에 전달하며, 플레이어가 AJA/DeckLink 출력 포트를 별도로 점유하지 않습니다. 기존 플레이어 실행 파일이나 카드 출력 컨트롤러를 실행하는 방식이 아닙니다.

## 사용

1. 세션 정지 상태에서 **플레이어** 탭의 **SW 파일 입력 · INPUT 4 직접 연결**을 선택합니다. `INPUT 4 · 내장 플레이어`를 체크하고 `파일 열기`로 로컬 영상을 선택합니다.
2. 파일에 맞는 HD/UHD 세션을 선택합니다. `테스트 패턴 · SDI 사용 안 함`에서는 IN1~3 패턴 + IN4 파일을 카드 출력 없이 확인할 수 있습니다.
3. 실제 SDI 세션에서는 IN1~3과 PGM/PVW 포트를 선택합니다. IN4의 SDI 포트 선택은 비활성화됩니다.
4. `세션 시작` 후 첫 프레임이 CUE 상태로 표시됩니다. `재생`을 누르면 파일이 진행됩니다. IN4를 PVW에 선택한 뒤 CUT/AUTO로 PGM에 올립니다. 재생 시작과 CUT은 독립 동작입니다.
5. `일시정지`는 현재 화면을 유지하고 플레이어 오디오를 무음으로 합니다. `CUE / 처음`은 처음으로 돌아가 정지합니다. 슬라이더를 드래그해 탐색할 수 있습니다. `반복`을 끄면 파일 끝에서 마지막 화면과 무음을 유지합니다.

파일 교체나 IN4의 SDI/플레이어 전환은 세션을 정지한 상태에서 합니다. 재생 버튼은 파일을 자동으로 PGM에 올리지 않습니다. 기본 출력 음소거를 해제해야 SDI에 소리가 나갑니다. PC 스피커로의 오디오 모니터링은 아직 없습니다.

## 지원 범위

- UHD: 3840×2160, 60000/1001 fps, progressive.
- HD: 1920×1080, 30000/1001 fps, interlaced, top field first. 59.94 fields/s.
- 파일 확장자 MXF/MOV/MP4/MKV 등은 선택 가능하지만, 실제 코덱은 연결한 FFmpeg 빌드의 디코더가 지원해야 합니다.
- 영상은 현재 SW와 같은 8-bit UYVY / Rec.709 SDR로 변환됩니다. 원본 10-bit 정밀도는 유지하지 않습니다. 해상도·프레임률·주사 방식이 다른 파일은 오류로 알립니다. HDR/BT.2020은 SDR 변환 후 넣습니다. VFR/프레임 타임스탬프 불연속 파일은 대상이 아닙니다.
- 다채널 오디오 파일은 첫 트랙의 CH1/2, 모노 트랙이 여러 개면 첫 두 트랙을 L/R로 전달합니다. 모노 트랙이 하나면 양쪽으로 복제합니다. 48kHz signed 32-bit stereo로 변환하며 전체 트랙 다운믹스는 하지 않습니다.
- 출력 음소거, PGM/PVW 선택, AUTO 전환의 오디오 연결은 기존 SW 경로를 따릅니다. PIP 전경 소스의 오디오를 별도로 더하지 않습니다.

## 구조 및 진단

`native/media.cpp`는 별도 디코드 스레드와 최대 8프레임 선행 큐를 사용합니다. CPU 디코드를 기본 경로로 제공하고 지원되는 큰 영상에는 CUDA 하드웨어 디코드를 시도합니다. GPU 디코드 결과는 현재 CPU UYVY 버퍼로 전달되며, CUDA-D3D11 공유 텍스처 경로는 아닙니다. 영상 버퍼를 재사용합니다.

소비 속도는 SW 시계가 결정합니다. 파일 오디오는 합성 결과의 프레임 번호에 맞춰 전달하여 GPU 파이프라인의 한 프레임 지연과 맞춥니다. CUE/탐색 명령은 세대 번호로 구분해 이전 디코드 결과를 버립니다. 재생 대기 수치는 디코더 큐가 비어 영상을 유지하고 무음을 출력한 횟수입니다. 반복 경계는 재탐색이 발생하므로 무중단 루프를 보장하지 않습니다.

플레이어 영역에서 위치/길이, 큐 크기, 디코드 시간과 재생 대기를 확인할 수 있습니다. `--diagnostics` JSON에는 `player` 객체가 추가됩니다. 파일 오류는 플레이어 영역에 표시되고 다른 SDI 소스의 세션은 계속됩니다.

## 빌드와 확인

```powershell
.\scripts\prepare-player.ps1 -PlayerRoot 'Z:\Codex\KBC_Tech_Player_KONA5_20260909'
.\scripts\build.ps1
# 물리 카드에 접근하지 않는 파일+GPU 합성 확인
.\build\Release\sw_player_check.exe '영상 파일.mxf' --uhd
# GUI 로컬 시험 (IN4를 PGM/PVW에 지정, 파일 재생)
.\dist\SW\sw_switcher.exe --media '영상 파일.mxf' --uhd --play-media
```

다른 FFmpeg 개발 파일을 쓰면 `scripts/build.ps1 -FFmpegRoot 경로`로 지정합니다. 폴더에는 `include`와 MSVC `.lib` 및 DLL이 있는 `bin` 또는 `lib`가 필요합니다. CUDA SDK를 별도로 링크하지 않고 FFmpeg의 하드웨어 디코드 API를 사용합니다. 기존 플레이어 FFmpeg 빌드는 `nonfree`이므로 현재 패키지는 이 PC의 로컬 시험용입니다. DLL과 시험 영상은 GitHub에 올리지 않습니다. 자세한 구성은 `THIRD_PARTY_NOTICES.md`를 참고하세요.

자동 시험은 B-frame이 있는 합성 파일과 440/880Hz 두 모노 트랙을 생성하여 프레임 순서, 좌/우 오디오, CUE, 일시정지, 탐색, EOF, 반복, 잘못된 포맷과 파일 거부를 검사합니다. SDI 물리 출력·스피커 청감 확인과 실제 업무용 코덱별 장시간 검증은 별도입니다.

### 이 PC의 확인 결과

- Release 빌드 및 CTest 4개(코어, 시험 파일 생성, 플레이어, 라우팅) 통과. 플레이어 시험에는 8/10-bit planar·semi-planar YUV의 SIMD/나머지 픽셀 변환과 인터레이스 크로마 필드 분리 검사가 포함됩니다.
- 실제 UHD/HD 크기 MPEG-2 파일 + 테스트 패턴 3개 + GPU PGM/PVW 합성으로 각 약 5초 측정했습니다. HD는 약 59.89 ticks/s(29.97 frames/s 목표), UHD는 약 54.68 frames/s였습니다. 두 경우 플레이어 재생 버퍼 부족 0, PGM 오디오 약 -18.06 dBFS, 일시정지 후 -120 dBFS(무음), 모니터 50/50회 유효였습니다.
- UHD 영상 변환은 기존 범용 경로 약 14.5ms에서 SIMD 경로 약 4.5ms로 감소했습니다. 전체 UHD 59.94p 연속 운용 성능은 아직 충족 확인되지 않았습니다. 이 측정은 물리 SDI 출력 시험이나 모든 코덱의 성능 보장이 아닙니다.
- GUI에서 INPUT 4, PGM/PVW에 파일 화면 표시와 CUE의 처음 이동·무음 처리를 확인했습니다.
