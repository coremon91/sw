# KONA 입력 → DeckLink 출력 오디오 점검

## 시험 구성과 관찰

2026-09-10 사용자는 DeckLink를 사용하는 4K 플레이어 → KONA 입력 → SW → 별도 DeckLink 출력 구성에서 상하 흔들림은 사라졌지만 오디오가 깨지거나 나오지 않는다고 보고했습니다.

실제 SW 창에서 음소거 해제, UHD 세션, KONA SDI 3이 IN 2에 연결된 것을 확인했습니다. PGM은 IN 2, PVW는 무신호 IN 1을 선택했습니다. 따라서 PVW가 무음인 것은 해당 소스 선택에 따른 동작입니다. PGM 출력은 DeckLink (3), PVW 출력은 DeckLink (2)로 유지했습니다. 외부 플레이어의 출력 포트는 DeckLink (4)였습니다.

기존 실행 중 상태에서 오디오 부족 264회, 처리 지연 7,088회, 합산 I/O 드롭 95,618회를 읽었습니다. 기존 합산 드롭에는 무신호/입출력 상태가 섞여 있으므로 이것을 오디오 손실 샘플 수로 해석하지 않습니다.

## 수정한 문제

1. **호스트 시간 누적 지연**: 처리 마감이 조금만 늦어져도 매번 엔진 기준 시각을 뒤로 밀어 실제 처리율이 59.94Hz 아래로 내려갔습니다. 일반적인 지연은 절대 시각을 유지하며 따라잡고, 4틱을 넘는 큰 지연에만 기준을 재설정합니다.
2. **과거 시각의 출력 예약**: DeckLink 하드웨어 재생 시각은 계속 진행하는데 SW가 정한 출력 순번만 증가했습니다. 이제 실제 하드웨어 시각과 비교해 늦어진 예약을 앞쪽으로 복구하고, 영상과 오디오에 같은 프레임 시각을 사용합니다. 복구 시 짧은 공백은 발생할 수 있으며 복구 횟수를 표시합니다.
3. **오디오 입력 버퍼**: 짧은 입력 지터에도 부족한 샘플 뒤를 무음으로 채워 즉시 내보냈습니다. 이제 20ms의 추가 여유를 확보한 뒤 시작하고, 부족하면 불완전한 블록을 소비하지 않고 다시 버퍼링합니다. 100ms 상한을 넘겨 버린 샘플 수도 따로 기록합니다.
4. **부분 전송**: DeckLink가 오디오 패킷 일부만 받으면 전체 세션을 오류로 종료했습니다. 남은 데이터와 타임스탬프를 유지해 다음 제출 시 이어서 전송하도록 수정했습니다. 무제한 누적은 허용하지 않습니다.
5. **음소거 버퍼 재사용**: 동일 크기 벡터에 `resize(..., 0)`를 호출하면 이전 내용이 지워지지 않았습니다. 출력 버퍼를 매번 초기화해 음소거 때 이전 오디오가 남지 않게 했습니다.
6. **무신호 입력 부하**: 무효 신호에 대해 전체 UHD 프레임을 RAM으로 복사하지 않도록 바꿨습니다. 무신호 횟수와 I/O 드롭을 분리했습니다.
7. **진단**: 입력 CH 1/2 피크, PGM/PVW 피크, 오디오 부족·버퍼 초과·출력 시계 복구, 출력 드라이버의 오디오 버퍼 수를 추가했습니다. 피크는 PCM 데이터 측정이며 실제 스피커에서 소리가 들렸다는 증거는 아닙니다.

DeckLink의 부분 전송 반환값, 예약 시각과 하드웨어 시계는 [공식 IDeckLinkOutput 문서](https://sdk-doc.blackmagicdesign.com/decklink-sdk/DeckLinkAPI/interfaces/idecklinkoutput.html)를 기준으로 확인했습니다. 오디오 콜백 등록은 선택 사항이므로 콜백 부재 자체를 결함으로 판단하지 않았습니다. AJA의 24bit PCM은 32bit 워드의 상위 비트를 사용하는 [공식 데이터 형식](https://sdkdocs.aja.com/public/ntv2/dev/d5/d32/dataformats.html)이며 이번 점검에서 바이트 순서를 임의로 바꾸지 않았습니다.

## 실행과 진단

오디오 수정본은 `dist/SW-audio-v3/sw_switcher.exe`입니다. 입력/출력 카드와 포맷을 확인하고 전체 SDI 모드에서 사용합니다. DeckLink/KONA 수신 확인 모드는 물리 오디오를 출력하지 않습니다.

이번 시험 재현 명령은 다음과 같습니다. 다른 프로그램이 SW가 사용할 입력/출력을 점유하지 않는 상태에서 실행합니다. `--ports` 순서는 IN 1–4, PGM, PVW이며 장치 재검색 결과에 맞춰 지정해야 합니다.

```powershell
.\sw_switcher.exe --sdi --uhd --pgm 2 --unmute --ports aja:0:0,aja:0:2,aja:0:1,aja:0:3,decklink:2,decklink:1 --diagnostics audio-status.json
```

`--diagnostics`는 1초마다 최신 상태를 로컬 JSON 파일로 원자적으로 교체합니다. 음성이나 영상 자체는 저장하지 않습니다. 기본 실행은 자동으로 실제 SDI를 열지 않으며 출력 음소거 상태로 시작합니다.

## 검증과 범위

- CTest 코어·포트 검사 통과. HD/UHD 오디오 시각의 샘플 수 일치, 지연 후 재예약, 스테레오 연속성, 초기 버퍼링/재버퍼링, 상한 처리와 피크값 검사를 포함합니다.
- UHD 엔진의 시작·CUT·DVE·AUTO·정지 검사 통과. 외부 플레이어와 기존 SW가 함께 실행된 4개 합성 패턴 부하에서는 6.15초간 266틱이었으므로 전체 UHD 성능 충족으로 해석하지 않습니다.
- 반대 방향 KONA 실제 수신, PGM에 유효 PCM 데이터와 출력 드라이버 오디오 버퍼 존재를 확인했습니다.
- 추가 시간 보정 후 무음 구간 30.239초: 엔진 59.956틱/초, 새 오디오 부족/버퍼 초과/PGM 드롭/출력 복구 각각 0.
- 이 무음 구간에서는 외부 플레이어가 23:22의 끝 프레임에 머무는 것을 26초 간격의 두 화면에서 확인했습니다. 같은 파일을 CUE 후 재생하여 유효 음성 구간으로 시험을 이어갔습니다.
- 유효 음성 구간 29.231초: 엔진 59.936틱/초, 입력과 PGM의 30회 관측 전부 유효 PCM, 새 오디오 부족 0, 버퍼 초과 0, PGM 드롭 0, 출력 시계 복구 0, 세션 오류 없음. 샘플 처리율은 입력 약 47,970/초, 출력 약 47,997/초로, 1초 단위 비동기 관측과 패킷 경계 오차를 포함합니다.
- 화면에서 IN 2와 PGM 피크 약 -13.2dBFS, PVW 무음을 확인했습니다. 물리 SDI 재수신이나 스피커 청취 검증으로 대체 해석하지 않습니다.

장시간 클럭 차이를 보정하는 비동기 오디오 리샘플링, 샘플 단위 A/V 지연 정렬, CH 3–16 선택/다채널 믹싱은 아직 구현하지 않았습니다. 오디오는 각 입력 CH 1/2의 48kHz 스테레오가 해당 PGM/PVW 배경 영상을 따릅니다. 최종 청감 및 장시간 운용 검증은 별도로 확인해야 합니다.
