# 2026-09-09 구현 검증 기록

## 환경

- Windows 11 Pro x64, Visual Studio Community 2026 / MSVC 19.51, Windows SDK 10.0.26100.
- Qt 6.8.3, AJA NTV2 18.0.0 (`4add45239a03960aa36de6fef326ee1b753e8ec9` + 기록된 MSVC 호환 패치).
- NVIDIA GeForce RTX 5060.
- AJA KONA 5 드라이버 18.0.0.1053, DeckLink 8K Pro 드라이버 16.4.0.0.

## 확인된 사항

Release 빌드 성공. CTest의 코어·포트 검사 2개 통과. 코어 검사는 장면 분리, 디졸브 시간, HD 필드/프레임 구분, 48kHz 오디오의 소수 프레임 주기, 프레임 풀 소유권을 확인했습니다. 포트 검사는 중복·방향·미지원 포맷을 거부했습니다.

HD/UHD GPU 픽셀 검사에서 PGM/PVW 분리, CUT, PIP 합성 및 불투명도, HD의 서로 다른 상위/하위 필드를 확인했습니다. 네이티브 Qt 화면은 자체 화면 저장 기능으로 실행 및 한글 표시를 확인했습니다. 자동 화면 시험은 테스트 패턴을 사용하며 SDI를 활성화하지 않습니다.

장치 검색 결과 DeckLink 8K Pro의 4개 하위 장치는 HD와 UHD의 SDI 모드를 지원한다고 응답했습니다. KONA는 `Kona5-8K`, 장치 ID `276399106`, `CanDo12gRouting=true`로 응답했고 4개 SDI 채널이 검색됐습니다. 이는 장치 능력 조회 결과이며 동시 부하 시험 완료를 의미하지 않습니다.

## 성능과 제한

캐시된 입력을 사용하는 GPU 합성 검사에서 120틱 평균은 HD 약 1–2ms, UHD 약 5.7–7.6ms였습니다. 이 값은 물리 캡처, 매 프레임 전체 입력 업로드, 카드 출력 비용을 포함하지 않습니다.

움직이는 UHD 패턴 4개를 CPU에서 생성하고 업로드하며 PGM/PVW를 읽어오는 전체 엔진 시험에서는 목표 59.94p에 미달했습니다. 최적화 중 6.15초 동안 약 236–288틱(약 38–47틱/초)이 관측됐고 시간 초과가 발생했습니다. 실행 환경과 합성·모니터 부하에 영향을 받습니다. **현재 버전으로 UHD 4입력·2출력의 실시간 지속 운용을 보장하지 않습니다.** HD 엔진의 명령 전달, CUT/DVE/AUTO와 정지 시험은 통과했으나 이 또한 장시간 SDI 무결성 인증이 아닙니다.

엔진은 출력 리드백에 한 프레임의 파이프라인 지연을 두고 해당 영상의 오디오 선택 장면도 함께 지연시킵니다. GPU 모니터는 합성 화면을 묶어서 내려받습니다. 다음 성능 작업은 입력 DMA/업로드 및 출력 리드백의 복사량 감소, 하드웨어 시계 기준 스케줄, 비동기 프레임 동기화입니다.

## 첫 UHD 루프백 시험

사용자가 요청한 KONA → DeckLink 방향으로 12초 진단을 실행했습니다. AJA SDI 1 출력과 DeckLink 4개 입력을 UHD 2160p59.94로 초기화했습니다.

- KONA로 전달한 영상: 719프레임.
- DeckLink 유효 영상 수신: 4개 채널 모두 0프레임.
- 고유 프레임 마커 일치: 0. `signal_verified=false`.
- 시험 종료 후 입력·출력 스트림을 정지하고 AJA 저장 설정 복원을 시도했습니다.

케이블 연결이 확인되지 않은 상태의 첫 결과입니다. DMA 전달 성공만으로 SDI 신호 송수신 성공을 판단하지 않습니다. KONA SDI 1과 DeckLink 입력의 12G 케이블 연결, 포트 대응, 신호 잠금 상태를 확인한 후 재시험해야 합니다. 초기 도구의 종료 대기 150ms 동안 발생할 수 있는 의도된 출력 언더런을 측정에서 제외하도록 후속 수정했습니다.

후속 기록에는 실제 연결 포트, 출력별 프레임 마커, 수신 속도·누락·반복, 4입력·2출력 전체 부하, 오디오 동기를 추가해야 합니다.
