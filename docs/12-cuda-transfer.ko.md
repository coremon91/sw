# SW 0.4 — D3D11 합성 + CUDA 전송

0.3과 별도 폴더에 설치하는 개발 버전입니다. 실행 파일은 이 프로젝트의 `dist/SW/sw_switcher.exe`입니다. 0.3 실행 파일을 덮어쓰지 않습니다.

## 처리 방식

- CG Key/Fill, DVE, CUT/AUTO, 색 변환은 기존 D3D11 셰이더를 사용합니다.
- CUDA는 입력의 고정 시스템 메모리→D3D11 텍스처 업로드와 D3D11 합성 결과→출력용 고정 메모리 전송을 담당합니다.
- 입력과 출력 프레임 저장소를 페이지 정렬하고 CUDA에 한 번 등록하여 재사용합니다. 프레임 복사/크기 변경 시 이전 등록을 공유하거나 유지하지 않습니다.
- CUDA 출력은 KONA에 전달하는 Frame 버퍼에 직접 기록합니다. 이전의 D3D staging→Frame CPU memcpy를 생략합니다. GPU와 RAM 사이의 전송 자체는 남습니다. GPUDirect P2P 구현은 아닙니다.
- 출력 프레임과 해당 장면 상태를 함께 한 프레임 지연해 전달합니다. CUDA 전송 완료 및 소비자의 프레임 반납 전에는 버퍼를 재사용하지 않습니다.
- 물리 출력으로 지정되지 않은 PGM/PVW 버스의 전체 크기 출력 읽기를 생략합니다. 모니터 합성은 계속 수행합니다.

FFmpeg CUDA/NVDEC 파일 디코딩과 SDI CG 합성은 별개의 기능입니다. 0.4 전송 변경은 파일 디코더를 CG 합성기로 바꾸는 기능이 아닙니다.

## 실행과 구분

- 일반 EXE: CUDA를 시도하며 초기화가 지원되지 않으면 D3D11 경로와 이유를 표시합니다.
- `SW-0.4-CUDA.cmd`: CUDA 경로를 강제합니다. 지원되지 않으면 세션 오류로 표시하여 조용히 다른 경로로 바뀌지 않습니다.
- `SW-0.4-D3D11.cmd`: 비교를 위한 기존 D3D11 전송 경로입니다.
- 상태 표시의 `D3D11 + CUDA pinned transfer`로 CUDA 사용 여부를 확인할 수 있습니다.
- 설정은 `SW/Switcher-0.4`에 저장합니다. 첫 실행 시 0.3 설정을 읽어 복사하며 이후 0.3 설정에는 쓰지 않습니다.
- 0.3이 사용하는 SDI 포트를 0.4에서 동시에 열 수 없습니다. 실제 비교 시 한 프로그램의 세션을 정지한 뒤 다른 버전의 세션을 시작하세요.

## 스크롤 CG

출력 프레임 누락은 스크롤의 정지/점프로 보일 수 있으므로 이번 최적화의 개선 대상입니다. 그러나 원본 CG 출력 프레임레이트, Key/Fill 시간 정렬, 장치 출력 큐의 지연은 별도 요소입니다. 이 버전은 외부 Key/Fill을 타임스탬프로 재동기화하지 않습니다.

데스크톱의 일반 세션 미리보기는 여전히 4틱마다 갱신합니다(약 15fps 목표). 미리보기의 스크롤과 59.94fps SDI 출력의 움직임을 구분하세요. 최종 판정은 실제 SDI 출력에서 해야 합니다.

## 빌드

Qt/FFmpeg/AJA SDK/CMake는 기본적으로 인접한 기존 `SW` 폴더를 개발 의존성으로 사용합니다. CUDA 헤더/라이브러리는 이 프로젝트의 `.deps/cuda`를 사용합니다. 완성된 dist 패키지의 기본 스위처 실행에는 소스 폴더가 필요 없습니다.

`scripts/build.ps1`로 빌드·검사·패키징합니다. CUDA Runtime 12.9.79, NVCC 헤더 패키지 12.9.86을 사용하며 NVCC 커널 컴파일이나 CUDA Toolkit 시스템 설치는 필요하지 않습니다. NVIDIA 드라이버와 동봉 CUDA runtime DLL이 필요합니다.

## 검증 범위

구체적인 실행 결과는 `local-qa/v04-validation.md`를 확인하세요. 자동 검사는 물리 SDI 포트를 점유하지 않습니다. 실제 입력/출력의 장시간 무드롭 및 외부 Key/Fill 동기 검증은 별도 장치 시험입니다.
