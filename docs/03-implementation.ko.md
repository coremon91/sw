# SW 0.1 사용 안내

Windows C++20, Qt 6 Widgets, Direct3D 11로 만든 개발 버전입니다. 기본 전환과 DVE를 실제 픽셀에 적용하는 엔진, DeckLink 캡처·예약 재생, AJA AutoCirculate 캡처·재생 코드를 포함합니다.

## 실행

`dist/SW/sw_switcher.exe`를 실행합니다. 같은 폴더의 Qt DLL과 `platforms` 폴더도 필요합니다. Visual C++ x64 런타임과 카드 드라이버를 설치해야 합니다.

1. **테스트 패턴** 또는 **실제 SDI**를 선택합니다.
2. HD 또는 UHD 세션을 선택합니다. 실행 중에는 포맷과 포트 변경이 잠깁니다.
3. SDI 모드에서는 입력 4개, PGM 출력, PVW 출력을 지정합니다. 같은 포트 중복 지정은 거부합니다.
4. **세션 시작**을 누릅니다. 처음에는 출력 오디오가 음소거됩니다.
5. 입력 버튼 또는 1–4로 PVW를 선택합니다. **CUT / Space**는 즉시 전환, **AUTO MIX / Enter**는 지정 프레임 수의 디졸브입니다.
6. DVE에서 PVW의 PIP 소스, 위치·크기·크롭·회전·불투명도·테두리를 편집합니다. CUT/AUTO로 장면 전체를 PGM에 반영합니다. 전환 중에는 충돌하는 편집이 잠깁니다.
7. **정지** 후 모드와 포트를 바꿀 수 있습니다. 종료 시 스트림을 중단하고 AJA 설정 복원을 시도합니다.

정지 시 마지막 모니터 영상이 남고 **STOPPED**로 표시됩니다. 신호가 500ms 이상 갱신되지 않으면 검은 화면과 **NO SIGNAL**을 표시합니다. 테스트 모드의 **TEST**는 물리 SDI 출력 상태가 아닙니다.

## 포맷과 처리

| 항목 | 현재 구현 |
|---|---|
| HD | 1920×1080, 30000/1001 프레임/초, 상위 필드 우선 60000/1001 필드/초 |
| UHD | 3840×2160, 60000/1001 프레임/초 |
| 세션 | HD 또는 UHD 하나. 입력 4개도 세션 포맷과 일치해야 함 |
| 합성 | Direct3D 11 하드웨어 GPU, Rec.709 제한 범위 SDR |
| I/O 픽셀 | UYVY 8-bit 4:2:2. 10-bit v210 경로는 후속 작업 |
| DVE | PIP 1개, 위치·크기·크롭·회전·불투명도·흰 테두리 |
| HD 처리 | 입력 프레임을 두 출력 필드 동안 보관; 필드별 합성 후 교차 행으로 출력 |
| 오디오 | 48kHz 32-bit 스테레오, PGM/PVW 배경 영상에 따른 선택 및 디졸브 혼합 |
| 진단 | 신호 상태, 처리 시간, 시간 초과, I/O 드롭, 오디오 부족 횟수 |

오디오는 20ms의 추가 여유를 둔 제한 큐로 전달하며 부족 시 다시 버퍼링합니다. 입력/출력 레벨, 부족·버퍼 초과·출력 시간 복구 횟수를 표시합니다. 비동기 리샘플링, 정밀 A/V 지연 보정, 믹서·리미터는 아직 없습니다. DVE 소스의 오디오는 배경에 합산하지 않습니다. [오디오 수정 및 시험 결과](07-audio-validation.ko.md)를 참조하세요.

## 카드와 루프백

### 외부 4K 플레이어 → KONA → 스위처 DeckLink 수신 확인

장비가 부족할 때 입력 한 개만 연결하여 확인하는 모드입니다. `DeckLink-receive.cmd`를 실행하거나 프로그램에서 **DeckLink 수신 확인 · 출력 없음**을 선택합니다. 이 모드의 장치 검색과 스트림 시작은 DeckLink만 사용하고 KONA는 외부 플레이어가 사용합니다.

1. 외부 4K 플레이어에서 KONA 5 출력 포트를 지정하고 **3840×2160p59.94** 영상을 재생합니다.
2. 해당 KONA SDI 출력을 DeckLink SDI 입력에 12G-SDI 케이블로 연결합니다.
3. 스위처 수신 확인 모드에서 **UHD · 2160p59.94**, 연결된 **DeckLink 입력 채널**을 IN 1에 선택합니다. 나머지 입력은 **사용 안 함**으로 둡니다. 입력 1–4개를 선택할 수 있습니다.
4. **세션 시작**을 누릅니다. 영상이 표시되고 유효 수신 프레임 수가 계속 증가하는지, 수신 속도가 약 59.94fps인지 확인합니다. 개선 버전은 모니터 처리도 59.94회/초를 목표로 합니다. 입력 FPS와 화면 처리 FPS는 별도이며 PC 모니터의 실제 표시 주사율을 보장하는 수치는 아닙니다.
5. 신호가 없으면 `NO SIGNAL`로 표시합니다. 포트 연결과 플레이어 출력 포맷을 확인합니다. 현재 2160p29.97/30/60 등 다른 UHD 프레임 레이트는 자동 변환하지 않습니다.

이 모드의 PGM/PVW는 **LOCAL · 출력 없음**으로 표시되는 화면 미리보기입니다. SDI 출력이나 스피커 오디오 재생은 하지 않습니다. 첫 선택 입력을 두 화면에 표시하고, CUT/DVE도 화면에서 시험할 수 있습니다. 출력 포트 지정은 필요 없습니다. 외부 플레이어가 KONA를 사용하는 동안 아래 `UHD-loopback.cmd`는 실행하지 마세요. 해당 도구는 KONA 출력을 직접 사용합니다.

반대 방향은 `KONA-receive.cmd` 또는 **KONA 5 수신 확인 · 출력 없음**을 사용합니다. DeckLink에서 출력 가능한 외부 플레이어를 사용해 DeckLink SDI 출력 → KONA SDI 입력으로 연결합니다. KONA 출력 플레이어를 먼저 종료하여 카드 점유를 해제해야 합니다. 제조사별 수신 포트 선택을 따로 저장하며, 수신 모드에서는 선택한 제조사의 입력만 사용합니다. 자세한 절차는 [양방향 수신 시험 안내](06-receiver-jitter.ko.md)를 참조하세요.

우선 시험 배치는 DeckLink 8K Pro 4입력, KONA 5 SDI 1 PGM / SDI 2 PVW입니다. 검색 결과에 따라 포트를 직접 지정합니다. 앱은 DeckLink 프로파일이나 카드 펌웨어를 자동 변경하지 않습니다.

AJA UHD 경로는 SDK가 `CanDo12gRouting`을 제공하는 독립 12G 프레임스토어 구성에 한정됩니다. 다른 펌웨어의 쿼드 링크 라우팅은 구현하지 않았습니다. SDK의 지원 여부만으로 동시 4입력·2출력의 신호 무결성과 성능을 보증하지 않습니다.

KONA SDI 1 출력과 DeckLink 입력을 12G-SDI 케이블로 연결한 뒤 실행합니다. 다른 프로그램이 해당 포트를 사용하지 않는 상태에서 시험합니다.

```powershell
.\dist\SW\sw_loopback.exe --uhd --seconds 12
# KONA 1·2를 DeckLink의 서로 다른 입력에 연결한 경우:
.\dist\SW\sw_loopback.exe --uhd --seconds 12 --outputs 2
```

처음 검색된 AJA 출력 1·2와 DeckLink 4개 채널을 사용하는 진단 도구입니다. 여러 카드가 설치된 환경에서는 이 기본 매핑을 먼저 확인하세요. 고유 마커·출력 버스·프레임 번호를 넣어 실제 재수신 여부, 누락, 반복, 수신 속도를 출력합니다. 케이블 없는 입력의 무신호는 루프백 실패 프레임으로 판정하지 않습니다.

## 빌드 및 검사

Windows x64, Visual Studio 2022 이상에서 **C++를 사용한 데스크톱 개발**과 Windows SDK를 설치합니다. Python 3와 Git도 필요합니다.

```powershell
.\scripts\bootstrap.ps1
.\scripts\build.ps1
.\scripts\run.ps1 -Demo
.\dist\SW\sw_probe.exe
.\dist\SW\sw_bench.exe
.\dist\SW\sw_bench.exe --uhd
.\dist\SW\sw_bench.exe --engine --uhd
```

기존 Qt는 `build.ps1 -QtRoot <경로>`로 지정합니다. `-NoAja`는 AJA를 제외합니다. DeckLink 어댑터는 빌드 시 설치된 Desktop Video DLL의 공개 COM 타입 라이브러리를 사용하며 생성 헤더와 제조사 DLL을 저장소에 올리지 않습니다.

`sw_bench`는 캐시된 입력으로 픽셀 정확성과 GPU 합성·리드백 비용을 검사합니다. `--engine`은 움직이는 패턴 4개 생성·업로드, 명령 전달, 전환, 정지까지 검사합니다. 모두 물리 SDI 검증과는 별개입니다. 루프백도 외부 입력 4개를 DVE 처리해 2개로 출력하는 전체 부하 시험을 대신하지 않습니다.

코어·포트 검사는 CTest로 실행합니다. GitHub Actions는 제조사 드라이버 없이 실행 가능한 코어 시험을 실행합니다. AJA 18.0.0의 최신 MSVC 호환 패치는 `scripts/patch_aja.py`에 기록했습니다.

## 남은 작업

- UHD 4입력 + PGM/PVW 2출력 지속 부하, 신호 무결성, 지연과 드롭 측정.
- 공통 레퍼런스/젠록 기준 출력과 비동기 입력 프레임 싱크. 현재 호스트 시계 기준으로 장시간 클럭 차이가 생길 수 있음.
- 10-bit, HDR/Rec.2020, 고품질 디인터레이스, 입력별 HD/UHD 혼합 변환.
- 방송용 오디오, ANC/타임코드, 녹화·스트리밍·자막·키어·매크로·세션 파일.
- 장치 재연결, 외부 프로파일 변경, 드라이버 오류 후 복구 시험.

기존 `index.html`과 `src/`는 웹 시안이며 실제 엔진과 연결되지 않습니다. 네이티브 구현은 `native/`, 테스트는 `tests/`, 문서와 측정 기록은 `docs/`입니다.
